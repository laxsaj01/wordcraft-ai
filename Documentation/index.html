WordCraft AI

AI SEO Content Writer & Article Generator — complete SaaS platform

Version 1.0.0 · Node.js + React · SQLite (zero DB setup)

1. Introduction

Thank you for purchasing WordCraft AI. It is a complete, self-hosted SaaS platform that lets your users generate marketing and SEO content with AI, chat with an assistant, save documents, buy credit plans, refer friends, open support tickets, and read your blog — all while you run the business from a built-in admin panel.

What you get

  • 12 AI writing templates — SEO blog articles, product descriptions, meta tags, Google Ads, social posts, marketing emails, paraphrasing, summaries, grammar fixes, keyword ideas, FAQs and landing-page copy.
  • Real-time streaming generation (Server-Sent Events) with a stop button.
  • AI chat assistant with conversation history.
  • Credit system with a full transaction ledger and automatic refunds when the AI provider fails.
  • Subscriptions & one-time packs via PayPal and Stripe.
  • Referral program that rewards users in credits.
  • Developer API (v1) with hashed keys for programmatic generation.
  • Blog / CMS with public, SEO-friendly pages.
  • Support ticket system.
  • Admin panel — stats, users, plans, payments, blog, tickets and settings.
  • 5 languages (English, Spanish, French, German, Arabic) with full RTL support.
  • Dark & light themes, fully responsive.
  • Works with any OpenAI-compatible API — OpenAI, DeepSeek, Groq, OpenRouter, Together, or a self-hosted model. No vendor lock-in.
WordCraft AI uses better-sqlite3, so there is no database server to configure. The database is a single file created automatically on first run. This makes installation as simple as npm install && npm start.

3. Installation

Step 1 — Unzip

Unzip the downloaded package. Open the wordcraft-ai folder in a terminal.

Step 2 — Install dependencies

npm install

Step 3 — (Optional) Build the frontend

A production build of the React frontend is already included in client/dist, so you can skip this. If you change any frontend source, rebuild with:

npm run build

Step 4 — Start the server

npm start

You will see:

WordCraft AI is running at http://localhost:3000
Open the URL in your browser to run the installation wizard.

Step 5 — Run the wizard

Open http://localhost:3000 in your browser. Because the app is not installed yet, you are redirected to the install wizard (see next section).

Changing the port: set the PORT environment variable before starting, e.g. PORT=8080 npm start (Linux/macOS) or set PORT=8080 && npm start (Windows).
Data location: the SQLite database is stored in data/wordcraft.sqlite. Back up this single file to back up everything (users, documents, plans, payments, blog, tickets, settings). You can relocate it with the WCAI_DATA_DIR environment variable.

4. Install Wizard

The wizard appears only on first run (while the app is not installed). It creates your administrator account and seeds the default plans and settings.

After submitting, the system:

  1. Creates the admin user with a large credit balance.
  2. Seeds three plans: Starter Pack ($9 one-time, 100 credits), Creator ($19/month, 300 credits), Business ($49/month, 1200 credits, API access).
  3. Sets sensible defaults: signup bonus = 10 credits, referral reward = 20%, AI base URL = OpenAI, model = gpt-4o-mini.

The wizard can only be run once. To reset the app to a fresh state (for example before handing it to a client), stop the server and delete the data folder, then start again.

8. AI Chat

Create a chat, then send messages. Each message costs chat_cost_credits (default 1). The assistant keeps the last 20 messages as context and uses the system prompt you set in Admin → Settings → AI Provider. Responses stream in real time and the full conversation is persisted.

9. Credits & Plans

Credits are the internal currency. Every generation, chat message and API call spends credits; buying a plan adds them.

  • Signup bonus — new users receive signup_bonus_credits (default 10) automatically.
  • Plans — one-time packs add credits once; subscriptions add credits and extend the plan expiry each billing cycle. Renewals stack the expiry date forward.
  • Ledger — every credit movement (spend, purchase, refund, signup, referral, admin adjustment) is recorded and visible to the user under Profile → Transactions (and via GET /api/transactions).

10. Referrals

Each user has a unique referral code and link (?ref=CODE). When a referred user makes a qualifying purchase, the referrer earns referral_reward_percent of the purchased credits (default 20%). The Referrals page shows the link, total earned, and the list of referred users (emails masked for privacy).

11. Payments

Both gateways are integrated with raw HTTPS calls (no SDKs), so there is nothing extra to install. Configure them in Admin → Settings → Payments. If a gateway is not configured, checkout returns a friendly message instead of crashing.

PayPal

SettingValue
PayPal Modesandbox or live
PayPal Client IDFrom your PayPal REST app
PayPal SecretFrom your PayPal REST app

Create an app at developer.paypal.com. The return URL is <site_url>/billing/return?gateway=paypal.

Stripe

SettingValue
Stripe Secret Keysk_test_... or sk_live_...

Stripe Checkout is used (hosted payment page). The success URL carries {CHECKOUT_SESSION_ID}.

Set site_url in Admin → Settings → General to your public URL so payment redirects return to the right place.

Fulfilment flow

  1. User clicks checkout → the server creates a PayPal order or Stripe session and returns a redirect URL.
  2. User pays on the gateway, then returns to /billing/return.
  3. The client calls POST /api/billing/confirm, which captures/verifies the payment.
  4. On success, credits are added, the plan expiry is extended, the payment is recorded, and any referral reward is granted.

13. Blog / CMS

Write posts in the admin panel and publish them to a public, paginated blog at /blog. Each post has a unique slug, an excerpt, Markdown content, a view counter and a status (draft/published). Only published posts appear publicly. Markdown is rendered by a built-in, XSS-safe renderer (all HTML is escaped).

14. Support Tickets

Users can open up to 5 concurrent tickets. Admins see all tickets, reply, and change status. When an admin replies the ticket becomes answered; when the user replies it returns to open. The full message thread is preserved.

15. Developer API (v1)

Users on a plan with API access (e.g. Business) — or any admin — can generate content programmatically. Keys are created under API Keys and start with wc_. They are stored hashed (SHA-256) and shown only once.

Authentication

Authorization: Bearer wc_your_key_here

Endpoints

MethodPathDescription
GET/api/v1/templatesList templates with their fields and costs.
GET/api/v1/creditsCurrent credit balance.
POST/api/v1/generateGenerate content for a template.

Example

curl -X POST https://your-site.com/api/v1/generate \
  -H "Authorization: Bearer wc_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
        "template": "seo-meta",
        "inputs": { "keyword": "crm software", "page": "Our CRM product page" }
      }'

Response:

{
  "template": "seo-meta",
  "content": "...generated text...",
  "credits_used": 1,
  "credits_remaining": 42,
  "usage": { ... }
}

16. Languages & RTL

Five locales ship in client/src/locales: en, es, fr, de, ar. The language selector is in the top bar. Choosing Arabic sets dir="rtl" on the document and the whole layout mirrors correctly. The choice persists in localStorage.

Adding a language

  1. Copy en.json to xx.json in client/src/locales and translate the values.
  2. Register it in client/src/i18n.jsx (add to the locales map and, if RTL, to the RTL list).
  3. Add the option to the language <select> in AppLayout.jsx.
  4. Rebuild with npm run build.

18. Deployment

Run in production with PM2

npm install -g pm2
pm2 start server.js --name wordcraft
pm2 save
pm2 startup      # follow the printed command to enable on boot

Environment variables

VariablePurposeDefault
PORTHTTP port3000 (or the saved setting)
WCAI_DATA_DIRFolder for the SQLite file./data

Reverse proxy (Nginx)

Put Node behind Nginx and proxy to it. Because generation uses SSE, disable proxy buffering on the API path:

location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_buffering off;        # required for streaming
  proxy_cache off;
}
Always serve the app over HTTPS in production so JWTs and API keys are protected. Set site_url to your HTTPS URL.

19. FAQ & Troubleshooting

better-sqlite3 fails to install

It usually downloads a prebuilt binary. If it tries to compile and fails, install build tools (see Requirements), ensure Node is v18+, then run npm install again. You can also try npm rebuild better-sqlite3.

Generation returns an error / 502

Check Admin → Settings → AI Provider: the Base URL (must end in /v1), the API key, and the model name. Credits spent on a failed call are refunded automatically.

Checkout says the gateway is not configured

Add your PayPal and/or Stripe credentials in Admin → Settings → Payments, and set site_url in General settings.

I locked myself out / want a fresh start

Stop the server, delete the data folder, and restart. The install wizard will appear again. (This erases all data.)

The page is blank after deploying

Make sure client/dist exists (run npm run build if not) and that your proxy forwards /api to Node.

Streaming does not work behind a proxy

Disable proxy buffering/caching for the API path (see the Nginx example).
